# Neurons · src/contracts

refreshed 2026-10-17 · 4cf30dae33e3

- `src/contracts/tank/**` is vendored generated code from `tactical-agent-neural-knowledge/contracts`, copied in by sha. Editing it by hand is a listed prohibition — run `pnpm sync-contracts <contracts-sha>`, which deletes and replaces the whole tree.
- `src/contracts/VERSION` records the contracts sha the SDK is built against (currently `b9ec4798a1f67029bfb9b719058feef5947f3cc4`); it is the only place that answers "which proto revision is this".
- **New in this refresh**: `catalog` package added at `src/contracts/tank/catalog/v1/catalog_pb.ts` — `CatalogService`, `ProductCard`, `Portfolio`, sort enums, and stats/analytics types (`BoardStatsResponse`, `Tally`, `Series`, etc.). It has a flat shim (`src/contracts/catalog.ts`) but no `export * as catalog` line in `src/contracts/index.ts`.
- **New in this refresh**: `agent_pb.ts` gained a `model` field on `TreadSettings`, carrying the model id the workspace's switchboard uses (empty string means TANK decides). `MODEL_CHOICES` in `src/client/models.ts` enumerates valid values.
- `src/contracts/index.ts` is a **hand-maintained** namespaced barrel (`export * as agent`, `as auth`, `as blocks`, …) and exists so same-named messages in different packages cannot collide. A new proto package needs a line added to this barrel by hand; the sync script does not touch `index.ts`.
- The flat per-package shims (`src/contracts/agent.ts`, `catalog.ts`, etc.) *are* generated and carry the header `// Generated by scripts/sync-contracts.sh — do not edit.`; they back the `./contracts/*` wildcard subpath, so `…/sdk/contracts/catalog` resolves without any extra export entry.
- There are more shims than barrel namespaces: `admin`, `agentctl`, `billing`, `catalog`, `command`, `monitor`, `platform` and `topo` have a flat shim but no `export * as` line in `index.ts` — reach them through `…/sdk/contracts/<pkg>`.
- `@bufbuild/protobuf` v2 shapes are used directly as the store's message types; there are no parallel DTOs, so a proto field rename lands straight in `src/client/store.ts`.
- Messages are plain objects carrying a `$typeName` literal, which is what lets `EventPayload` in the store be a closed union of `tank.events.v1` types plus `{ $typeName: "unknown", typeUrl, value }` and still narrow in a `switch`.
- `biome.json` excludes `src/contracts/tank` from lint and format, so generated style never has to match repo style — but the flat shims and `index.ts` *are* linted.
- After any sync: `pnpm build` and commit the rebuilt `dist/`, or CI's `git diff --exit-code dist/` step fails.
