# Neurons · src/contracts

refreshed 2026-10-04 · 6a1f2b084d98

- `src/contracts/tank/**` is vendored generated code from `tactical-agent-neural-knowledge/contracts`, copied in by sha. Editing it by hand is a listed prohibition — run `pnpm sync-contracts <contracts-sha>`, which `rm -rf`s `src/contracts/tank` and replaces the whole tree.
- `src/contracts/VERSION` is the single answer to "which proto revision is this": currently `3e5911da5826d6dcf885218f6820cab19a81e790`, bumped three times since the last refresh (`e3d381f` → `f878ed8` → `3e5911d`).
- The convention for a contracts bump is one commit per sha, message `contracts <short-sha>: <what moved>`, carrying `src/contracts/**` *and* the rebuilt `dist/contracts/**` together — see `6a1f2b0`; splitting them fails CI's `git diff --exit-code dist/`.
- `src/contracts/index.ts` is a **hand-maintained** namespaced barrel (`export * as agent`, `as auth`, `as blocks`, …) so same-named messages in different packages cannot collide — e.g. `SetStatusRequest` exists in both `presence` and `agent`. The sync script never touches it; a new proto package needs a line added by hand.
- The flat per-package shims (`src/contracts/agent.ts`, `topo.ts`, `message.ts`, … 22 of them) *are* generated, carry `// Generated by scripts/sync-contracts.sh — do not edit.`, and are one line: `export * from "./tank/<pkg>/v1/<pkg>_pb.js"`. They back the `./contracts/*` wildcard subpath, so `…/sdk/contracts/message` resolves with no extra `exports` entry.
- Trap: the shim loop in `scripts/sync-contracts.sh` only *writes* shims, it never deletes them. If a package disappears upstream its stale `src/contracts/<pkg>.ts` survives and then fails typecheck pointing at a missing `tank/<pkg>/v1`; delete it by hand after a sync that drops a package.
- There are more shims than barrel namespaces: `admin`, `agentctl`, `billing`, `catalog`, `command`, `monitor`, `platform` and `topo` have a flat shim but no `export * as` line in `index.ts` — reach them through `…/sdk/contracts/<pkg>`.
- Neural Knowledge now has wire types here and **nothing outside `src/contracts` consumes them yet**: `tank.agent.v1.TreadSettings.readNeuralKnowledge`, `tank.agentctl.v1.RunContext.skipNeuralKnowledge` / `StartRunRequest.skipNeuralKnowledge` / `.mode` (`""` ordinary, `"neural"` refresh) / `.repo`, and the `ControlService.RefreshNeuralKnowledge` + `OpenThread` RPCs. Wiring them into `src/client/store.ts` is open work, not a regression.
- `TreadSettings` also gained `pullRequests` (`"review"` default, or `"merge_when_green"`) and `prReviewerIds`; `tank.topo.v1.GetBriefingResponse` gained `hours: BriefingHour[]` and `setup?: BriefingSetup`; `tank.workspace.v1.HomeLayout` gained `setupHidden`.
- `@bufbuild/protobuf` v2 shapes are used directly as the store's message types — no parallel DTOs — so a proto field rename lands straight in `src/client/store.ts`.
- Messages are plain objects carrying a `$typeName` string literal, which is what lets `EventPayload` in the store be a closed union of `tank.events.v1` types plus `{ $typeName: "unknown", typeUrl, value }` and still narrow in a `switch`.
- Scalar fields are non-optional with zero defaults and message fields are `?:` (`hour?: Timestamp`), so absence is `undefined` on submessages only — never test a missing `int32` for `undefined`.
- `biome.json` excludes `src/contracts/tank` from lint and format, so generated style never has to match repo style — but the flat shims and `index.ts` *are* linted.
- After any sync: `pnpm build` and commit the rebuilt `dist/`, or CI's `git diff --exit-code dist/` step fails.
