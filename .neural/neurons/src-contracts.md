# Neurons · src/contracts

refreshed 2026-10-07 · 93fc7f8ed552

- `src/contracts/tank/**` is vendored generated code from `tactical-agent-neural-knowledge/contracts`, copied in by sha. Editing it by hand is a listed prohibition — run `pnpm sync-contracts <contracts-sha>`, which deletes and replaces the whole tree.
- `src/contracts/VERSION` now records `77435ec229ee930c7b7ce688a4f6634b7113cfca` — it is the only place that answers "which proto revision is this".
- This sync vendors two brand-new top-level packages and expands a third, none of which the SDK consumes yet: `board` (`board_pb.ts`) — `Board`/`BoardSummary`/`BoardObject`/`AppFrame`/`BoardTemplate`/`BoardSlice`/`BoardEmbed`/`ReportPreview`/`ReportBoardSource`/`Derivation` plus full CRUD, `PutObjects`, `ExportBoard`, `GenerateTest`, `DeriveDiagram`, and an `ObjectKind` enum; `canvas` (`canvas_pb.ts`, entirely new) — `Canvas`/`CanvasSummary`/`Block`/`Table`/`TableRow`/`Decision`/`DecisionRecord`/`Live`/`Source`/`Template` plus full CRUD and `UpdateBlock`; `books` (`books_pb.ts`, entirely new, the Neuralbooks domain) — `Settings`/`Customer`/`Invoice`/`InvoiceLine`/`Payment`/`Expense`/`CashSummary` plus full CRUD including `SendInvoice`/`RecordPayment`/`VoidInvoice`/`RecordExpense`.
- `events_pb.ts` gained matching event messages — `CanvasBlockChanged`, `CanvasChanged`, `CanvasEditing`, `BoardObjectsChanged`, `BoardChanged`, `BoardPointer` — and `realtime_pb.ts` grew `canvasIds`/`boardIds` fields on the subscribe/unsubscribe messages to carry them (see `src-client.md` for how `RealtimeClient` uses these; `store.ts` imports the four `*Changed` types only to widen `KnownEventPayload`, with no handling behind them).
- `src/contracts/index.ts` is a **hand-maintained** namespaced barrel (`export * as agent`, `as auth`, `as blocks`, …) and exists so same-named messages in different packages cannot collide — e.g. `SetStatusRequest` lives in both `presence` and `agent`. A new proto package needs a line added here by hand; the sync script does not touch `index.ts`.
- `board`, `canvas` and `books` each got a flat shim (`src/contracts/board.ts`, `canvas.ts`, `books.ts`) but **no barrel entry** — reach them only through `…/sdk/contracts/board` etc., not `contracts.board`. The barrel now covers 14 packages; the full set of shim-only packages (flat shim, no namespace in `index.ts`) is `admin`, `agentctl`, `billing`, `board`, `books`, `canvas`, `catalog`, `command`, `monitor`, `platform`, `topo` — eleven, up from eight last refresh.
- The flat per-package shims (25 of them) *are* generated and carry the header `// Generated by scripts/sync-contracts.sh — do not edit.`; they back the `./contracts/*` wildcard subpath, so `…/sdk/contracts/board` resolves without any extra export entry even though the barrel doesn't know about it.
- Cross-cutting gap worth knowing before building on any of the three: `src/client/client.ts` has no Connect client for `board`, `canvas` or `books` (confirmed by grep — zero matches), so right now they are vendored contract surface only, reachable by hand-wiring a `createClient(...)` against the shim, not through `TankClient`.
- `@bufbuild/protobuf` v2 shapes are used directly as the store's message types; there are no parallel DTOs, so a proto field rename lands straight in `src/client/store.ts`.
- Messages are plain objects carrying a `$typeName` literal, which is what lets `EventPayload` in the store be a closed union of `tank.events.v1` types plus `{ $typeName: "unknown", typeUrl, value }` and still narrow in a `switch`.
- `biome.json` excludes `src/contracts/tank` from lint and format, so generated style never has to match repo style — but the flat shims and `index.ts` *are* linted.
- After any sync: `pnpm build` and commit the rebuilt `dist/`, or CI's `git diff --exit-code dist/` step fails.
